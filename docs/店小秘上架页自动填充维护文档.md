# 店小秘上架页自动填充维护文档

更新时间: 2026-05-21

## 目标

店小秘上架页自动填充由浏览器扩展 `extensions/amazon_collector/dianxiaomi_ozon.js` 执行，目标是把 sERP 产品数据填入 `https://www.dianxiaomi.com/web/{platform}Product/add` 这类创建页。

当前支持的页面匹配:

- Ozon: `/web/ozonProduct/add`、`/web/ozonProduct/edit`
- Wildberries: `/web/wildberrieProduct/add`、`/web/wildberrieProduct/edit`
- 其它平台按 `{platform}Product/add|edit` 自动识别平台名

## 自动填充分层

自动填充分两层执行:

1. LLM 语义映射
   - 输入: 产品标题、产品数据、实测/采集重量尺寸、成本价、变体列表、当前页面字段列表。
   - 输出: 字段 index 到待填充值的映射。
   - 适合: 标题、描述、属性、JSON 富文本、类目相关文本。

2. 程序确定性填充
   - 输入: 手工产品数据、采集规格、定价公式、页面字段 label。
   - 输出: 重量、尺寸、产地、价格、原价、库存等确定值。
   - 规则: 确定性字段会优先填入，并跳过 LLM 对同一字段的结果，避免价格/库存被模型误填。

## 发给 LLM 的关键数据

`doAutoFill()` 会构建请求体:

- `skc`
- `product_title`
- `product_data`
- `manual_data`
  - `cost_price`
  - `effective_weight_g`
  - `effective_size_spec`
  - `effective_weight_source`: measured 或 collected
  - `effective_size_source`: measured 或 collected
- `pricing_context`
  - `formula_id`
  - `sale_price_cny`
  - `old_price_cny`
  - `stock`
  - `variables`
- `form_fields`
- `variant_list`
- `variant_row_summary`
- `custom_prompts`

注意: 价格字段实际由程序填充，`pricing_context` 主要用于让 LLM 理解上下文，不能让 LLM 覆盖最终价格。

## 字段分类

### 确定性字段

这些字段不依赖 LLM:

- 重量: 优先 `manual_data.weight_g`，没有则用 `manual_data.collected_weight_g`
- 尺寸: 优先 `manual_data.size_spec`，没有则用 `manual_data.collected_size_spec`
- 产地: 默认中国
- 售价(CNY): 根据定价公式计算
- 原价(CNY): 根据售价乘原价倍率计算，默认 1.8 倍
- 库存: 默认 10000

### LLM 字段

这些字段适合继续由 LLM 判断:

- 商品标题
- 产品描述
- JSON 富文本
- 普通类目属性
- 平台/店铺/品类提示词影响的文本字段

## 店小秘控件类型清单

字段采集由 `collectFormFields()` 完成，填充由 `fillFormField()` 按控件类型分发。发送给 LLM 的 `form_fields` 里会带 `controlKind`，用于提示模型不要把有限选项当成自由文本。

| controlKind | 页面形态 | 典型字段 | 填充方式 | 成功标志/注意点 |
|---|---|---|---|---|
| `input-text` | 普通单行输入框 | 标题、颜色名称、SKU 文本 | 聚焦、全选、`insertText`，再触发 `input/change` | 店小秘联动字段通常还需要 `keyup/blur` 或行级 `change` |
| `input-number` | 数字输入框 | 重量、长宽高、价格、库存 | 原生 value setter 或 `insertText`，触发 `input/change` | 价格、库存优先走程序确定性规则 |
| `textarea` | 多行文本框 | 产品描述、普通长文本 | 聚焦、全选、写入，触发 `input/change` | 不要把 JSON 富文本误填到产品描述 |
| `json-editor` | “编辑JSON代码”弹窗 | JSON 富文本 | 点击按钮打开编辑器，优先写 CodeMirror，其次 textarea/contenteditable/剪贴板 | 写入后点击确定/保存；内容必须是合法 JSON |
| `native-select` | 原生 `<select>` | 少量老式下拉 | 按 value、文本、模糊文本、数字近似匹配 | 选中后触发 `change/input` |
| `ant-select-single` | Ant Design 普通单选 | 固定枚举字段 | 打开下拉，按可见选项精确/归一化/子串匹配 | 当前 DOM 必须有候选项 |
| `ant-select-search` | Ant Design 搜索单选 | `材料 (Материал)`、部分类目属性 | 输入候选词，触发 `input/change/compositionend/keyup`，等待远程候选项，再点击 | 不能只看初始 DOM；`Экокожа` 这类值要先搜索 |
| `ant-select-multiple-search` | Ant Design 搜索多选 | `商品颜色(Цвет товара)`、标签类多选 | 逐个候选词搜索并点击，最多按平台规则控制数量 | 颜色类字段要去重，Ozon 商品颜色最多按业务规则取 3 个 |
| `checkbox-group` | 多个 checkbox 组成一组 | 多选属性 | 根据选项文本归一化匹配；若找不到，尝试搜索型 checkbox 添加 | 适合有限可选属性 |
| `radio-group` | 多个 radio 组成一组 | 单选属性 | 根据选项文本归一化匹配后选中 | 只能选择一个 |
| `single-checkbox` | 独立 checkbox | 开关型字段 | 布尔值或文本匹配 | 只处理明确 true/false 或选项文本 |
| `single-radio` | 独立 radio | 少量单选开关 | 布尔值或文本匹配 | 一般较少见 |

特殊控件不完全走通用 `form_fields`:

- `变种主题`: 由 `ensureVariantThemeSelected()` 先选“颜色/Цвет”等主题。
- `变种行`: 由 `ensureVariantRowsForProduct()` 根据正式产品变体数量创建；选品弹窗“全部变体”关闭时只取第一个正式变体。
- `变种属性 - 商品颜色(Цвет товара)`: 有限可选，属于 SKU 颜色选择面板，走 `fillSkuColorCell()`，需要搜索候选并点击，不能直接写文本。
- `变种属性 - 颜色名称(Название цвета)`: 文本输入，写入后要触发输入框事件和 SKU 行级事件，推动“变种信息”同步。
- `变种图片`: 不自动填充；通过扩展“变种图”按钮手动选择图片集或单图。

## Ozon 定价公式

设置页的 `定价公式` 模块维护每个平台的公式。Ozon 默认公式:

```text
sale_price_cny =
ceil(
  (cost_price_cny
   + seller_logistics_cny
   + ozon_fixed_fee_cny
   + return_reserve_cny
   + other_fixed_cost_cny)
  /
  (1
   - profit_rate
   - ozon_commission_rate
   - acquiring_rate
   - promotion_rate
   - other_percent_fee_rate)
)
```

原价公式:

```text
old_price_cny = ceil(sale_price_cny * original_price_multiplier)
```

默认变量:

- `profit_rate`: 0.30
- `ozon_commission_rate`: 0.18
- `acquiring_rate`: 0.015
- `promotion_rate`: 0
- `other_percent_fee_rate`: 0
- `seller_logistics_cny`: 根据重量尺寸估算；设置值作为兜底
- `ozon_fixed_fee_cny`: 0
- `return_reserve_cny`: 0
- `other_fixed_cost_cny`: 0
- `original_price_multiplier`: 1.8
- `stock`: 10000

Ozon 佣金按品类变化。已有 Ozon 商品可通过 Ozon prices API 返回的 `commissions.sales_percent_fbs/fbo` 和 `acquiring` 覆盖默认值；新品创建前没有商品 ID 时用设置里的默认佣金。

## Ozon rFBS 物流估算

当前扩展内置了兴远 rFBS 的轻量估算，用于钱包类小件:

- `<= 500g`: `3.12 + 26 * kg`
- `<= 2000g`: `16.64 + 26 * kg`
- `> 2000g`: `37.44 + 17.68 * max(实重kg, 长*宽*高/12000)`

完整物流渠道和限制参考:

- `reference/兴远rFBS全渠道计算器2026-04-10.xlsx`

后续如果要做精确物流选择，应把 Excel 渠道规则结构化到设置或数据表，不要继续在扩展里堆 if/else。

## 填充页临时变量

选择产品后，左侧产品卡片里的“价格公式”可以展开并临时修改:

- `利润率(Profit)`
- `佣金(Commission)`
- `收单费(Acquiring)`
- `物流费(Logistics)`
- `原价倍率(Old x)`
- `库存(Stock)`

修改变量后点击“更新价格到页面”，扩展只会重算并回填 `售价(CNY)`、`原价(CNY)` 和 `库存`，不会重新执行完整“自动填充”，也不会改标题、描述、属性、JSON 富文本或变体。临时变量只影响当前店小秘页面，不写回设置；长期配置应在 sERP 设置页的“定价公式”里修改。

## 变体和图片边界

- 变体行创建由 `ensureVariantRowsForProduct()` 负责。
- 选品弹窗有“全部变体”开关，默认开启；关闭后只取正式产品变体列表里的第一个变体参与创建和填充。
- 变种主题/颜色等文本属性由字段解析和 LLM/字典匹配处理。
- `商品颜色(Цвет товара)` 是有限可选项，必须先打开候选面板/搜索候选项后再点击选项。
- `颜色名称(Название цвета)` 是文本输入，写入后需要触发 `input/change/keyup/blur` 以及 SKU 行级 change，店小秘才会同步更新“变种信息”里的颜色名称。
- 变种图片不自动填充；通过“变种图”按钮手动选择图片集或单图，再复制 URL。

## 搜索型下拉字段

材料 `Материал` 等字段可能不是预渲染选项，而是远程模糊搜索:

1. 点击 Ant Select。
2. 输入目标值，例如 `Экокожа`。
3. 触发 `input/change/compositionend/keyup`。
4. 等待远程候选项出现。
5. 点击候选项。

维护时不要只检查当前 DOM 里有没有选项；这类字段需要输入关键字后才会出现候选项。

## 维护建议

1. 店小秘页面结构变化时，优先更新字段采集和 label 归一化，不要直接改 LLM prompt 硬凑。
2. 价格、库存、重量、尺寸这类确定性字段应继续走程序规则。
3. 新平台接入时先在设置页创建平台公式，再补平台字段 label 识别。
4. 每次扩展行为变更都更新 `SERP_EXTENSION_VERSION` 和 `manifest.json` 的版本号。
