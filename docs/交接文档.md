## 2026-05-21 店小秘自动填充：平台定价公式
- Chrome 扩展版本更新到 `3.2.15`。

- 新增维护文档：`docs/店小秘上架页自动填充维护文档.md`。

## 2026-05-21 产品管理页采集重量尺
- 产品详情左侧现在同时展示“采集重量/采集尺寸”和“实测重量/实测尺寸”；如果已录入实测值，对应采集值会灰色显示，避免把采集数据误认为实测数据。
- 新增 `POST /api/products/<skc>/collect_specs`：从产品采集数据中调用 LLM 结构化提取重量尺，要求模型返回 JSON，并统一换算为国际单位 `g` 和 `cm`。
- 提取结果会经过程序校验：字段结构、数值范围、`size_cm` 维度数量和单位格式不合格会自动重试；连续失败会返回错误，不写入缓存。
- 提取后会再调用独立审核模型做二次校验，审核结果与证据写入 `manual_data.collected_specs_*`，不会覆盖人工录入的实测 `weight_g` / `size_spec`。
- 设置页新增功能模型绑定：`产品重量尺提取` 和 `产品重量尺审核`；`.env.example` 新增 `DEEPSEEK_REVIEW_MODEL`。

## 二、启动方式

### 2.1 后端启动

```bash
cd g:\sERP
python main.py
# 访问 http://localhost:5000
```

### 2.2 浏览器扩展加载

1. 打开 Chrome → `chrome://extensions/`
2. 开启「开发者模式」
3. 点击「加载已解压的扩展程序」→ 选择 `g:\sERP\extensions\amazon_collector\`
4. 扩展 ID 需固定，确保 `chrome.storage` 数据不丢失

### 2.3 环境变量

`.env` 文件需配置（参考 `.env.example`）：
- `DEEPSEEK_API_KEY` — DeepSeek API 密钥（品类翻译、品类匹配、属性/表单填充）

- `OZON_<STORE>_CLIENT_ID` / `OZON_<STORE>_API_KEY` — Ozon 店铺凭证；`data/stores.json` 只保存 `${ENV_NAME}` 占位符，避免明文凭证进入 git

### 关键数据流

```
Amazon 采集流程:
  浏览器打开 Amazon 产品页
  → content.js 提取标题/价格/属性/描述/图片URL
  → bgFetch → POST /api/browser-capture
  → 后端存储 product_data.json (不含图片URL)
  → 后台线程下载图片

店小秘自动填充流程:
  用户在店小秘打开 Ozon 产品添加页
  → dianxiaomi_ozon.js 注入左侧工具栏
  → 选品 → 智能分类 → 自动填充
  → collectFormFields() 扫描表单字段
  → 分批发送 POST /api/auto-fill/analyze (DeepSeek)
  → fillFormField() 逐个填入 (绕过 Vue v-model 受控组件)
  → 结果面板显示填充状态

品类树翻译流程:
  Ozon API → category_tree.json (缓存)
           → 展平 7998 节点
           → 逐批发 DeepSeek → translations.json (缓存)
           → 前端合并渲染

Ozon 上架流程:
  产品数据 + 品类树 → DeepSeek 匹配品类
                    → 获取品类属性
                    → DeepSeek 填充属性值
                    → 保存上架草稿
```

## 四、日志系统

### 4.1 架构

| 文件 | Logger 名称 | 说明 |
|------|-------------|------|
| `app.py` | `logging.config.dictConfig` | ★ 唯一日志配置入口，在模块顶层执行 |
| `app.py` | `__name__` → `app` | 所有 API 路由日志 |
| `collector.py` | `__name__` → `collector` | 采集引擎日志 |
| `main.py` | — | 仅加载 .env + 启动 Flask，不配置日志 |

### 4.2 日志格式

```
HH:MM:SS | INFO  | app | 消息内容
HH:MM:SS | WARN  | app | 警告内容
HH:MM:SS | ERROR | app | 错误内容
HH:MM:SS | DEBUG | app | 调试内容（品类匹配等）
```

### 4.3 关键设计决策

- **为什么 `dictConfig` 放在 `app.py` 顶部而不是 `main.py`？**
  Flask `debug=True` 的 reloader 在 Windows 上通过 `subprocess.Popen` 创建子进程，子进程不会执行 `main.py` 顶层代码。放在 `app.py` 顶部保证无论哪个进程导入都能生效。
- **为什么需要 `sys.stdout.reconfigure(encoding='utf-8')`？**
  Windows 终端默认 GBK 编码无法输出 ❌ ✅ 等 emoji，会导致 `UnicodeEncodeError`，日志消息被静默丢弃。
- **`disable_existing_loggers: False`** — 防止 Flask/Werkzeug 已有的 logger 被禁用

## 五、当前已知问题

### 🟢 已处理：SKU 多行相同标签字段被重复填充不同值

**文件**: `extensions/amazon_collector/dianxiaomi_ozon.js` → `collectFormFields()`

**症状**:
- Ozon 产品表单有多行 SKU/变体，每行都有相同标签的字段（如"统一计量单位中的商品数量"）
- 当前 `collectFormFields()` 收集的字段标签完全相同，LLM 无法区分属于哪个 SKU 行
- 导致同一字段在不同行被填入随机不同值

**根因**: `findLabel()` 只读取 Ant Design form-item label，不感知所在 SKU 行上下文

**处理结果（2026-05-20）**:
- `collectFormFields()` 现在识别店小秘当前 `myj-table / skuData-body / tr.render-container` 表格结构
- 表格内字段优先补表头标签，并把 SKU 行上下文附加到 label
- 后端 `/api/auto-fill/analyze` 对 LLM 返回的 index 做有效性校验，并让重要字段批次优先，重复 index 不再被常规批次覆盖

### 🟢 已处理：额外提示词未在自动填充时生效

**文件**: `dianxiaomi_ozon.js` → `collectCustomPrompts()`

**症状**:
- 用户保存了俄语提示词，但自动填充结果仍是英文
- `collectCustomPrompts()` 从 DOM 元素读取值，但 DOM 元素仅在面板打开时从 chrome.storage 恢复

**根因**: 页面刷新后 `loadAllHints()` 在 init 时调用，但此时 `detectStoreId()` 可能因页面未完全加载而返回 null，导致提示词未被加载到 DOM。后续 `collectCustomPrompts()` 读到空值

**当前状态**: `collectCustomPrompts()` 已直接从 `chrome.storage.local` 读取平台/店铺/品类提示词，不再依赖提示词面板是否打开。

### 🟡 问题 3：单位信息未传递给 LLM

**症状**: Amazon 使用盎司 (oz)、英寸 (in)、磅 (lb) 等单位，Ozon 使用克 (g)、厘米 (cm)。LLM 填充重量/尺寸时缺少单位换算上下文

**修复方向**: 在 `product_texts` 中追加单位信息，或在 system_prompt 中添加换算规则

### 🟡 问题 4：品类翻译偶有解析失败

**文件**: `app.py` → `_translate_categories_batch()`（ThreadPoolExecutor 并发翻译）

**症状**: 偶发某些批次 `✅ 成功解析 0 个翻译结果`；DeepSeek 返回格式偶有波动

**当前状态**: 已清理 markdown 代码块再 `json.loads()`，大部分正常。仍有少数因输出截断导致解析失败。

### 🟡 问题 5：品类匹配 DeepSeek max_tokens 偏小

**文件**: `app.py` → `ozon_match_category`，`max_tokens: 512`

当前品类匹配仅返回品类 ID，512 tokens 足够。如需返回更多属性建议，可调大到 1024。

### 🟡 问题 6：WB 选择器仍有少量 CSS Module hash 依赖

**文件**: `extensions/amazon_collector/content.js` → WB EXTRACTORS

**症状**:
- WB 使用 CSS Modules，类名后缀（`--nrkiv`, `--JBcnf`, `--Xne45`）每次前端构建都会变
- 当前已添加 text content 和 attribute fallback，但 fallback 也有局限：
  - `_findByText(["Характеристики", "описание"])` — 扫描全页 button/span/div，O(N) 可能误匹配
  - `_findLongTextInDrawer()` — 依赖 `.mo-drawer__paper` 容器在 DOM 中，Floating UI 关闭时不存在
  - `[class*=\"price--\"]` — 同样依赖 CSS Module 前缀不变

**当前缓解（2026-05-20）**:
- 描述与规格优先读取 `data-testid='product-page-description'` / `product_additional_information`
- drawer 打开状态由 `waitForDrawerOpen()` 等待真实 DOM 内容出现
- 价格仍保留 `[class*="price--"]` fallback，后续如 WB 价格结构变化需继续替换为更稳定来源

**根治方向**: 用 `data-testid` 属性（WB 已稳定使用）替代所有 CSS class 选择器；或改用子资源完整性哈希检测构建变更。

### 🟢 已处理：WB 单采 Floating UI drawer — 轮询重试

**文件**: `extensions/amazon_collector/content.js` → `collectCurrent()`

**症状**:
- Floating UI portal 在 React hydration 后关闭状态时 drawer content 不在 DOM 中
- `_ensureDrawerOpen()` 点击按钮后 React 18 异步批处理渲染，可能数百毫秒后才出现内容
**处理结果（2026-05-20）**:
- 新增 `waitForDrawerOpen()`，最多等待 6 秒，并在等待期间按需重试点击详情按钮
- 单采和全部规格采集都会先等待 WB 详情 drawer 可读，再构建 `product_data`

### 🟢 已处理：批量替换产品图参考图缓存旧图

**文件**: `app.py` → `upload_ref_image()`

**症状**: "替换目标参考图"删除后第二次拖拽新图，页面仍显示第一次上传的图。

**根因**: 后端固定保存为 `_ref_1.jpg` / `_ref_2.jpg`，前端 URL 不变，浏览器命中旧缓存。

**处理结果（2026-05-20）**: 上传参考图时使用唯一文件名，并清理同一参考位旧文件，避免旧 URL 缓存继续生效。

### 🟢 已处理：采集产品数据夹带图片 URL 噪声

**文件**: `app.py` → `_sanitize_product_payload()`、`browser_capture()`

**症状**: Amazon/WB 采集结果中的 `product_data` / 任务摘要夹带大量变体图片 URL，不利于后续上架字段提取。

**处理结果（2026-05-20）**: `product_data.json` 和采集任务摘要只保留变体名称、价格、规格、描述、图片数量等业务字段；远程图片 URL 仅用于下载流程和 `images_mapping.json` 追踪。
